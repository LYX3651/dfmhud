# DFMHUD 实现说明

给接手的人看：这份代码在做什么、哪里是真空、怎么补。

## 一、架构决策记录

### 为什么是独立 App，不是注入 dylib

派大星.RS.R 实测证据：

| 证据 | 值 | 含义 |
|---|---|---|
| `Info.plist` 的 `NSPrincipalClass` | `HUDMainApplication` | 是 App 本体，不是 dylib |
| `CFBundleURLName` | `ch.xxtou.hudapp` | 用的是 Lessica 的 HUDApp 模板 |
| `cryptid` | 0，`filetype` = 2 (MH_EXECUTE) | 可执行文件 |
| entitlements | `task_for_pid-allow` + `accessibility-window-hosting` | 跨进程读 + 跨 App 悬浮 |
| imports | `_mach_vm_read_overwrite` / `_mach_vm_write` | 从自己进程读写别的进程 |

所以它**不在游戏进程里**。这让「注入检测」「代码完整性校验」整类问题直接消失——游戏里没有我们的字节。

### 那三档方法选哪个

`KernelSelectViewController` 的 `initWithKernelSupport:smith:physpuppet:` 说明它用的是 kfd。`__const` 段里那串 `kernelSymbol.*` 是铁证：

```
kernelSymbol.allproc                    kernelSymbol.cpu_ttep
kernelSymbol.kalloc_data_external       kernelSymbol.gVirtBase/gPhysBase
kernelSymbol.ptov_table                 kernelSymbol.pmap_enter_options_addr
kernelSymbol.ppl_trust_cache_rt         kernelSymbol.hw_lck_ticket_reserve_orig_allow_invalid
kernelStruct.proc.struct_size           kernelStruct.task.itk_space
kfd-posix-semaphore
```

配 `libgrabkernel2`（从 appledb 拉 kernelcache）和 `api.appledb.dev` 的 URL，是完整的 kfd 自举链。

**但我们的实现没照抄这一点。** 理由：kfd 的 offset 表是硬编码的，每换一个小版本就得重编。我们先走 `task_for_pid`（TrollStore 的 entitlements 直接给），kfd 只作兜底。

## 二、三层自适应

### 层 1：内存访问（`Mem.mm`）

```
task_for_pid(self) 成功  ──► Backend::TaskForPid
        │
        └─ 失败 ──► dlopen("kfd") ──► 依次试 landa / physpuppet / smith
                                              │
                                              └─ 全失败 ──► Backend::None
```

kfd 的 API 用 `dlsym` 拿，不 `#include` 头文件——因为不同分支的签名不一样（`kfd_init` / `dynamic_kfd_init` / `kfd_open` 都有）。这样 CI 拉不到 kfd 也能编过。

### 层 2：UE 表定位（`UE.cpp:Init()`）

`GObjects` / `GNames` 用三条候选特征码扫：

```
48 8B 3D ?? ?? ?? ?? 48 85 FF 74 ?? 8B 47
48 8B 0D ?? ?? ?? ?? 48 85 C9 74 ?? 8B 41
48 8B 05 ?? ?? ?? ?? 48 85 C0 74 ?? 8B 50
```

命中后按 `指令 + 7 + disp32` 解 RIP 相对寻址，得到表地址。

**关键设计**：拿到地址不算完，还要验证。`UE.cpp` 里那段 3/3 校验——取前 4096 个对象，看能不能用当前 profile 的 `ObjectsNum`/`Objects` 偏移正确取出对象并解出类名。三个 profile 里哪个能过就用哪个：

```cpp
{"UE4.23-5.3 (64K chunk/16B item)", 0x10000, 16, 0x24, 0x20},
{"UE4.23-5.3 (64K chunk/24B item)", 0x10000, 24, 0x24, 0x20},
{"UE4.20-4.22",                     0x10000, 16, 0x1C, 0x18},
```

这一步是「不写死版本」的核心。派大星每版重编，这里换版本会自己挑对。

### 层 3：字段偏移（`UE.cpp:FindPropertyOffset()`）

沿 `UClass.Children` 链找同名 `UProperty`，读它的 `Offset_Internal`。UE4 和 UE5 两套候选位置都试：

```cpp
// Children 链：UE4.27 +0x48 / UE5 +0x50
for (int childrenOff : {0x48, 0x50}) { ... }
// Offset_Internal：UE4 +0x4C / UE5 +0x54
for (int off : {0x4C, 0x54}) { ... }
```

只有反射链走不通时才用常量兜底（比如 `PersistentLevel` 兜底 `0x30`、`Actors` 兜底 `0xA0`）。

## 三、必须承认的真空

### 1. 特征码是通用 UE 模式，不是这个客户端的实测值

三角洲 iOS 版如果改过 `GObjects` 装载序列（腾讯常改），三个 pattern 会全 miss。日志会明确报：

```
[ue] GObjects 特征码全部未命中，需要按版本补偏移
```

**补法**：IDA/Ghidra 打开游戏主二进制，搜 `GObjects` 字符串或它的初始化函数，把 ARM64 指令序列写成 pattern 加进 `kGObjectsPatterns`。

### 2. 骨骼没实现

`GetBoneLocation()` 直接 `return false`。要真出骨骼线，需要：

- `USkeletalMeshComponent::BoneArray` 的偏移
- 目标骨架的骨骼索引表（`head` / `neck_01` / `spine_03` ... 在数组里是第几个）

这两个都只能靠真机 dump。接口已留好，`GetKeyBones()` 里有一份 UE4 Mannequin 的标准骨骼名，对上就能用。

### 3. 属性名是按通用 UE 猜的

`PlayerState` / `Health` / `MaxHealth` / `TeamID` / `CurrentWeapon` —— 这是 UE 的常见命名，但三角洲用的 GAS（GameplayAbilitySystem）可能把血量放在 `AttributeSet` 里，那就读不到。

**诊断方式**：跑自检，看日志里哪些 `FindPropertyOffset` 返回 -1。

### 4. 物资等级/价值是猜的

`LootLevelOf()` 靠类名关键词（`Helmet_Lv3` → 3、`MZJ_8X` → 4）。不是读游戏内真实数据。

### 5. 过直播没接实现

配置项 `liveMode` 存在但没生效。派大星那边是 `SystemUikit` 的 `disableSecureMode` / `enableSecureMode`，实现思路是改 `CAMetalLayer` 的 secure 属性，让 ReplayKit 抓不到。这里留空。

## 四、调试方式

TrollStore 环境不能挂 lldb（会触发反调试），所以全靠面包屑。

### 日志位置

```
/var/mobile/Library/Caches/dfmhud.log     ← no-sandbox 生效时
<App沙盒>/Library/Caches/dfmhud.log        ← 兜底
```

实时看：

```bash
idevicesyslog | grep DFMHUD
```

### 自检

菜单 → 系统 → 「跑全链路自检」，会弹窗列出 12 项：

```
[OK]   self task_for_pid     kr=0(0x0)
[OK]   backend               task_for_pid
[OK]   target proc           pid=12345 DeltaForceClient
[OK]   attach                pid=12345
[OK]   modules               187 imgs, main=/.../DeltaForceClient.app/DeltaForceClient base=0x104000000
[FAIL] UE init               特征码未命中
[FAIL] GObjects/GNames       obj=0x0 names=0x0
...
```

哪一行 FAIL 就从那层往下查。

## 五、构建

Windows 上没有 iOS SDK，走 GitHub Actions：

```bash
cd dfmhud
git init && git add -A && git commit -m "init"
# push 到 GitHub，Actions 自动出 DFMHUD.tipa artifact
```

macOS 本地：

```bash
brew install ldid
git clone --recursive https://github.com/theos/theos.git ~/theos
export THEOS=~/theos
./build.sh
```

要启用 kfd 内核后端：

```bash
git clone --depth 1 https://github.com/felix-pb/kfd third_party/kfd
./build.sh
```

## 六、装到设备

1. `DFMHUD.tipa` 传到 iPad（AirDrop / Filza / 文件 App）
2. TrollStore 打开它 → Install
3. 桌面出现「DFMHUD」图标
4. 启动 → 左侧蓝色球「D」→ 点开菜单 → 战斗 → 启用绘制
5. 切到游戏，悬浮层应保留（Accessibility 模式）

**注意**：如果自检里「跨App悬浮 API」是 FAIL，说明 `SBSAccessibilityWindowHostingController` 不可达，HUD 只在本 App 前台可见。这时需要换方案（见 `Overlay.mm` 注释）。
